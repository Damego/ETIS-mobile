# Адаптация ETIS-mobile под iOS (базовый минимум, сборка через EAS)

## Context

Приложение сейчас Android-only: `platforms: ['android']`, нет `ios.bundleIdentifier`, в JS-коде 33 вызова `ToastAndroid` (падают на iOS), unguarded `sp-react-native-in-app-updates` (crash при старте iOS release), Android-only файловые операции (SAF + intent). Цель — чтобы `eas build -p ios` собирал рабочий app: iOS-специфичный нативный функционал (quick actions icons, in-app updates) НЕ портируем, только безопасные гварды. Решения пользователя: bundle ID `com.damego.etismobile` / `dev.damego.etismobile` (DEV), CI-воркфлоу не трогаем, тосты на iOS → системный `Alert` фолбэк.

Проект — чистый CNG (`ios/` и `android/` в `.gitignore`), EAS сам выполнит prebuild. Notifee, expo-background-task (плагин сам добавит `BGTaskSchedulerPermittedIdentifiers`), @expo/ui, secure-store — уже iOS-совместимы, не трогаем. Babel-алиас `react-native-device-info` → стаб (`src/plugins/react-native-device-info.js`) оказывается load-bearing: iOS-стаб `sp-react-native-in-app-updates` импортирует этот пакет — оставить как есть.

## Изменения

### 1. Новый `src/utils/toast.ts`
`showToast(message: string, duration: 'short' | 'long' = 'short')`: Android → `ToastAndroid.show(message, SHORT/LONG)`; iOS → `Alert.alert(message)` (системный алерт с кнопкой OK). Плюс экспорт через barrel `src/utils/index.ts`, если паттерн позволяет.

### 2. Замена ToastAndroid (22 файла, ~33 вызова)
Механическая правка по списку из разведки (AuthLoadingModal, FileTextLink, useActionAvailability, useTimeTableQuery, Auth, ChangePassword, ChangeEmail, MessageHistory, MessageInput, Order, Teacher, TeacherBottomSheet, ToggleSentrySetting, ToggleSignNotification и др.): убрать `ToastAndroid` из импорта `react-native`, добавить `showToast`, `ToastAndroid.show(x, ToastAndroid.LONG)` → `showToast(x, 'long')` / `showToast(x)`.

### 3. `src/utils/inappUpdate.ts`
Ранний возврат `if (Platform.OS !== 'android') return undefined;` перед `if (!__DEV__)` — на iOS не создаем `SpInAppUpdates` и не вызываем `checkNeedsUpdate`. Остальное без изменений.

### 4. `src/utils/files.ts`
- `saveFileFromCache`: ранний возврат на iOS (`Directory.pickDirectoryAsync` — SAF, Android-only); файл остаётся доступен через share sheet.
- `openFile`: Android — текущий IntentLauncher; iOS — `void shareAsync(uri)` (expo-sharing уже используется в проекте, см. FileTextLink:86).

### 5. `src/utils/shortcuts.ts`
`addShortcuts`: ранний возврат на iOS — иконки шорткатов (`iosIcons`) не настроены, нативный функционал не портируем (комментарий с причиной).

### 6. `app.config.js`
- `platforms: ['android', 'ios']`.
- Блок `ios`: `bundleIdentifier: IS_DEV ? 'dev.damego.etismobile' : 'com.damego.etismobile'`, `buildNumber: '1'`, `supportsTablet` остаётся.

### 7. `eas.json`
Добавить профиль для теста без Apple-аккаунта:
```json
"ios_simulator": { "ios": { "simulator": true } }
```
`production` остаётся пустым (валиден для iOS app-store сборки).

### 8. Мелочи
- `.gitignore`: добавить `ios/` (рядом с `android/`) — на случай локального `expo run:ios`.
- `AGENTS.md`: обновить "(no iOS)" + короткая секция про iOS (EAS-сборка вручную `eas build -p ios`, что не портировано).
- `assets/icon.png` (1024×1024, RGBA с альфой): App Store Connect требует непрозрачную маркетинговую иконку. Если есть инструмент (ImageMagick/PIL) — свести на белый/`#CE2539` без изменения имени файла; если нет — задокументировать как обязательный шаг перед submit (на саму EAS-сборку/TestFlight альфа не влияет… TestFlight требует валидацию ASC — тогда тоже нужен шаг).
- Если `expo-doctor` пожалуется на платформенную поддержку `sp-react-native-in-app-updates` / `expo-intent-launcher` — добавить их в `expo.doctor.reactNativeDirectoryCheck.exclude` в package.json.

## Проверка

1. `bun run lint` — чисто (CI-гейт).
2. `bunx tsc --noEmit` — 0 ошибок.
3. `bunx expo-doctor` — 21/21 (или каждая проблема объяснена).
4. `bunx expo prebuild -p ios --no-install` — smoke-тест конфиг-плагинов на iOS (результат gitignored).
5. Android-поведение не меняется (тосты идентичны, гварды аддитивны) — подтверждается гейтами выше.
6. Реальная сборка — действие пользователя (платные минуты EAS + Apple-аккаунт): `eas build -p ios --profile production` или без кредов `eas build -p ios --profile ios_simulator`. Не запускаю автоматически.
